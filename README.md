# Sentinel AI — ИИ-Ассистент Дежурного

**Готовый демонстрационный B2B-продукт для кейса №8 хакатона ТПУ.**

Получает активные предупреждения из **настоящего Prometheus HTTP API**, хранит инциденты в PostgreSQL, классифицирует (категория/критичность/приоритет), подбирает инструкции из базы регламентов с помощью векторного поиска, отображает рекомендации и предлагает инженеру ручной чек-лист действий. Автоматических команд на серверы не отправляет.

## Быстрый запуск — Windows / macOS / Linux

**Требования:** Docker Desktop с Compose v2 (или Docker Engine с Compose), 4 ГБ свободной RAM, доступ к Docker Hub и пакетным реестрам при первой сборке, свободные порты 8080 и 9090. Node.js/Python **устанавливать на компьютер не требуется**.

1. Распакуйте ZIP в обычную папку (без кириллицы в пути желательно) и откройте в ней PowerShell/Terminal.
2. Создайте переменные окружения:
   - Windows PowerShell: `Copy-Item .env.example .env`
   - macOS/Linux: `cp .env.example .env`
3. Для локального демо подходят значения `.env.example`. **Если публикуете проект в сети — ОБЯЗАТЕЛЬНО поменяйте `JWT_SECRET`, `POSTGRES_PASSWORD`, `DEMO_PASSWORD`, `DEMO_TOKEN`.** Для генерации JWT-секрета можно использовать Python: `python -c "import secrets; print(secrets.token_hex(32))"`.
4. Из папки проекта:

   ```bash
   docker compose up --build -d
   ```

   Если у вас старая версия Compose: `docker-compose up --build -d`.
5. Откройте: **http://localhost:8080**.

| | |
|---|---|
| Вход администратора | **admin** / **DemoPass123!** (если не меняли `.env`) |
| Вход оператора | **operator** / **DemoPass123!** |
| React интерфейс | http://localhost:8080 |
| Swagger/OpenAPI backend | http://localhost:8080/docs |
| Prometheus | http://localhost:9090 |
| Логи всех сервисов | `docker compose logs -f --tail=100` |
| Остановка | `docker compose down` |
| Удалить ВСЕ локальные данные (осторожно!) | `docker compose down -v` |

Swagger доступен по адресу `http://localhost:8080/docs`, API-схема по `http://localhost:8080/openapi.json`. Также приложена зафиксированная спецификация `contracts/openapi.yaml`.

**При первой сборке** Docker скачивает изображения, Python и Node зависимости; может потребоваться несколько минут и интернет. Статус: `docker compose ps`, логи: `docker compose logs -f api worker scheduler prometheus`.

## Как показать работу (полный путь от Prometheus до интерфейса)

1. Войдите как `admin` → «**Симулятор**» → запустите «Высокая загрузка CPU».
2. Скрипт устанавливает gauge `demo_incident_active{scenario="cpu_high"} 1` в **реальном exporter**. Prometheus скрейпит метрику каждые 5 секунд; alert rule `HighCPUUsage` переходит в `firing`. Celery синхронизирует `/api/v1/alerts` каждые 8 секунд.
3. Через ~5–25 секунд откройте «**Инциденты**». Появится реальная запись в PostgreSQL. AI worker рассчитает классификацию (`critical`, `server`, `P1`) и предложит подходящий регламент с объяснением и процентом сходства.
4. Нажмите «**Взять в работу**» → «**Принять план реагирования**» → отмечайте инструкции «**Выполнено вручную**» или «Пропустить» с пояснением. Эти кнопки **никогда не запускают операции на инфраструктуре**.
5. «Симулятор» → «**Сбросить все сигналы**». Примерно через 10–30 секунд Prometheus перестанет публиковать alert; после двух успешных опросов статус мониторинга сменится на `resolved`.
6. Вернитесь в карточку, заполните результат реагирования (от 5 символов), нажмите «**Закрыть инцидент**». В «Хронологии» сохранится журнал.
7. Аналогично доступны 5 сценариев: CPU, диск, PostgreSQL, Nginx, потери сети.

**Не путайте**: «Выполнено вручную» означает подтверждение оператора, а не то, что AI что-либо выполнил. Для закрытия всегда нужны `acknowledged`, `monitor_state=resolved`, завершённые/пропущенные шаги и объяснение.

### AI и работа без внешних ключей

По умолчанию проект работает **полностью локально без платных API**, с классификатором по прозрачным правилам и векторизацией символьных n-грамм (`EMBEDDING_BACKEND=hash`). Это **легковесный векторный поиск**, но он не обладает семантическим пониманием на уровне трансформеров. Для настоящих multilingual semantic embeddings предусмотрен **опциональный режим multilingual-e5-small**:

- Добавьте в `backend/Dockerfile` после установки `requirements.txt` строку `RUN pip install --no-cache-dir -r requirements-ai-optional.txt` и скопируйте файл в образ до установки (либо установите через свой производственный Dockerfile).
- Поменяйте `.env`: `EMBEDDING_BACKEND=e5`.
- Учитывайте загрузку модели `intfloat/multilingual-e5-small` при первой инициализации (нужны интернет, оперативная память, дополнительное дисковое пространство). Созданные ранее векторные представления необходимо пересчитать или перезапустить на новой БД через `docker compose down -v` (это удаляет все локальные данные!).
- Базовый режим умышленно выбран основным, чтобы **одна команда Docker Compose гарантированно не требовала API-ключей или загрузки моделей во время старта**.

Системы **не обещают безошибочных диагнозов**. Порог 90% нужно дополнительно измерять на размеченном независимом наборе реальных инцидентов. В проекте есть воспроизводимый локальный синтетический benchmark.

## Архитектура

```
Browser → Nginx/React SPA → FastAPI REST API → PostgreSQL + pgvector
                       FastAPI → Redis → Celery worker (AI + Prometheus)
                                        ↑
                                Celery Beat (8 сек)
   Demo UI → FastAPI → demo-exporter → Prometheus alert rules → Prometheus API
```

- `frontend/` — React 19, TypeScript, Vite, TanStack Query, адаптивная SPA.
- `backend/app/main.py` — REST endpoints, валидация, RBAC.
- `backend/app/models.py` — SQLAlchemy ORM, PostgreSQL, pgvector.
- `backend/app/services.py` — импорт инцидентов, дедупликация, разбор инцидентов, журнал.
- `backend/app/ai.py` — классификация и ранжирование.
- `backend/app/tasks.py` — Celery/Redis задачи и расписание.
- `backend/app/bootstrap.py` — создание схемы (для MVP) и идемпотентное наполнение демо-данными.
- `exporter/` — реальный Prometheus metrics endpoint + внутреннее API управления.
- `prometheus/` — правила оповещений.
- `contracts/openapi.yaml` — спецификация API для параллельной разработки.
- `backend/tests/`, `scripts/` — тесты и проверка сквозного сценария.

В этом MVP схема БД создаётся идемпотентно через `Base.metadata.create_all` при старте. **Для изменения схемы после выпуска v1 требуются миграции Alembic**: `create_all` не изменяет существующие таблицы. Для хакатонной демо-версии используйте новую БД или сохраняйте совместимость структуры.

## Роли

- `admin`: доступ ко всем методам, добавление/изменение регламентов, симуляция, ручной sync.
- `operator`: просмотр, принятие инцидентов, выбор инструкций, отметка шагов, закрытие, перезапуск анализа.

JWT сроком 12 часов; пароль хеширован Argon2. Docker пробрасывает наружу только `localhost:8080` и `localhost:9090`; PostgreSQL, Redis и demo-exporter остаются внутри сети Docker. Демо-авторизация предназначена для хакатона, не production-ready IAM. Перед публичным деплоем: HTTPS, настоящие секреты, ограничения запросов, регулярные резервные копии, отключение демо-учётных записей, аудит безопасности.

## Локальные тесты

После установки Python 3.12 и зависимостей:

```bash
cd backend
pip install -r requirements-dev.txt
pytest -q
PYTHONPATH=. python ../scripts/evaluate_ai.py
```

После запуска контейнеров:

```bash
python scripts/smoke_test.py
```

Используется пароль из `DEMO_PASSWORD` (или по умолчанию `DemoPass123!`). Скрипт последовательно проверяет реальный поток Prometheus → БД → AI → API → подтверждение → reset → закрытие. Применять только к демонстрационному окружению: он создаёт и закрывает инцидент.

## Частые проблемы

- **Порт занят:** укажите `FRONTEND_PORT=8081` или `PROMETHEUS_PORT=9091` в `.env`, затем `docker compose up -d`; откройте `http://localhost:8081`.
- **Инцидент не появился:** проверьте `docker compose ps` и `docker compose logs -f prometheus worker scheduler`; в `http://localhost:9090/alerts` должен быть соответствующий alert; после запуска сценария подождите несколько циклов опроса.
- **Prometheus не подключён:** `docker compose logs --tail=100 worker prometheus`; при ошибках мониторинга приложение сохраняет состояние и **не отмечает инциденты устранёнными**.
- **ИИ не выдал рекомендацию:** проверяйте соответствующую категорию; система намеренно возвращает пустой список при отсутствии совпадений, а не сочиняет план реагирования.
- **Данные остались после перезапуска:** это нормально (том PostgreSQL); для демонстрации с чистого листа `docker compose down -v`.
- **Не меняйте POSTGRES_PASSWORD без переинициализации существующего тома**: PostgreSQL не обновляет пользователя автоматически.
- **Npm или pip не скачиваются при первой сборке:** требуется доступ к пакетным реестрам. Проверьте VPN/прокси/интернет Docker Desktop.

## Ограничения

Проект поставляется с исходным кодом и проверками статического характера, но **сборка всех Docker-образов и браузерный E2E не подтверждены в среде создания архива**, так как здесь недоступны Docker и внешние пакетные реестры. Обязательно выполните `docker compose up --build -d` и `python scripts/smoke_test.py` на вашей машине перед защитой. Кроме того, 91.7% — только результат небольшой синтетической выборки: для строгого утверждения о точности на реальных данных необходим отдельный размеченный датасет.
