# ML v1.7 — сравнение классификаторов в карточке инцидента

**Экспериментальная ветка:** `ml-comparison-ui-v17`. Стабильная `main` не изменена. Полный Docker Smoke Test выполняется на компьютере команды, а GitHub Actions проверяет Python-тесты и сборку React.

## Что изменилось

На карточке инцидента в блоке **«ИИ-анализ события»** добавлена кнопка **«Сравнить v1.1 и ML v1.6»**.

После нажатия система делает аутентифицированный **GET** `/api/v1/incidents/{incident_id}/analysis/compare` и показывает два ответа на **один и тот же инцидент**:

| Колонка | Алгоритм | Входные признаки |
| --- | --- | --- |
| Экспертные правила v1.1 | Ключевые слова, объяснимые правила | alert_name, title/summary, description |
| Обученная ML v1.6 | TF-IDF (слова + символьные n-граммы) + Linear SVM | Те же alert_name, title/summary, description |

Сравнение **намеренно не получает ни `severity`, ни `category` из меток Prometheus**. Более того, во избежание скрытой утечки v1.1 в сравнении получает `labels={}`, поскольку её исходный алгоритм анализирует все значения меток. Это справедливое **текстовое сравнение**, а не режим обычной обработки, где метка `severity` может задаваться внешним мониторингом.

Приоритет вычисляется для обеих колонок одной и той же политикой с учётом **окружения** `environment`/`env`. Поэтому приоритет является производным от severity и настройки окружения, а **не третьим независимым ML-предсказанием**.

Запрос ничего не записывает в PostgreSQL, не меняет выбранный регламент, принятые шаги, историю или текущий анализ. Сравнение проводится по кнопке, а не по каждому рефрешу интерфейса.

## Улучшения UI

- Жёлтое уведомление теперь корректно говорит об **обученной ML-модели**, когда анализ выполнялся SVM, и не утверждает, что это эвристический классификатор. Процент вероятности правильности SVM **не откалиброван** и потому не показывается.
- Регламенты с оценкой текстового сходства **ниже 30%** остаются доступны, но получают отметку **«Низкое сходство»** и предупреждение. Порог — условная визуальная подсказка, **не статистическая вероятность релевантности**.
- Две колонки рассчитаны на широкий экран и объединяются в одну на узком.
- В нижней части панели показано методологическое ограничение: совпадение прогнозов не доказывает их правильность и не является метрикой качества.

## Как запустить на Windows PowerShell

Скачайте ZIP ветки [`ml-comparison-ui-v17`](https://github.com/isingaque/B2B-Sentinel-AI/tree/ml-comparison-ui-v17), распакуйте в отдельную папку и перейдите в неё — в каталог, где лежат `docker-compose.yml` и `.env.example`.

```powershell
Copy-Item .env.example .env
notepad .env
```

Проверьте значения:

```dotenv
CLASSIFIER_ENGINE=context
FRONTEND_PORT=8085
PROMETHEUS_PORT=9095
```

Запуск **из каталога новой версии**:

```powershell
docker compose -p sentinel_ai_ui_v17 up --build -d
docker compose -p sentinel_ai_ui_v17 ps
```

Интерфейс: **http://localhost:8085**, логин `admin`, демонстрационный пароль `DemoPass123!`.

Откройте «Симулятор», активируйте событие, затем «Инциденты» → карточка события → «Сравнить v1.1 и ML v1.6».

Это **отдельный Compose-проект**, поэтому он не изменит БД стабильной v1.1 или ранее запущенной v1.6. При первом старте новая БД не содержит старых инцидентов: активируйте симулятор повторно.

Остановка без удаления данных:

```powershell
docker compose -p sentinel_ai_ui_v17 down
```

**Не используйте `down -v`**, если хотите сохранить данные.

## Как представить жюри

Рядом отображаются предсказания обеих моделей по категории, severity и производному priority. Если прогнозы расходятся, поля подсвечиваются. Отдельно можно продемонстрировать исходную метку `severity` Prometheus в реальном инциденте и объяснить, почему **нельзя выдавать её за самостоятельное предсказание ML**.

Достоверность модели нужно показывать через отдельные тесты на размеченных данных, а не через эту сравнительную карточку. Ранее измеренная совместная точность SVM v1.6 на 118 опубликованных правилах других экспортёров составляет **55,1% (65/118)**. Реальных зарегистрированных производственных инцидентов в этом корпусе нет.
