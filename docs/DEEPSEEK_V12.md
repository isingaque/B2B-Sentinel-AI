# Sentinel AI v1.2 — экспериментальная интеграция DeepSeek

**Статус:** отдельная ветка `ai-v1.2`. Стабильная версия v1.1 остаётся в `main`.

## Назначение

В экспериментальном режиме Backend направляет текст предупреждения в DeepSeek для определения категории, критичности и возможных причин. Нейросеть возвращает строго структурированный JSON; сервер проверяет поля, вычисляет приоритет и затем подбирает **только существующие активные регламенты**. Инженер выполняет и подтверждает шаги вручную.

По умолчанию `AI_PROVIDER=rules`: приложение не обращается к DeepSeek и полностью совместимо с v1.1. При ошибке API, отсутствии ключа или невалидном JSON автоматически используется прежний классификатор.

**Ограничение:** в этой ветке изменена классификация и объяснение; поиск регламентов по умолчанию остаётся прежним hash/pgvector. E5 — отдельный экспериментальный режим. Внешняя модель не исполняет команды и не добавляет собственные действия в чек-листы.

## Настройка

1. Получите **новый** API-ключ на https://platform.deepseek.com/ . Если ключ когда-либо был отправлен в чат, репозиторий или сообщение, отзовите его и замените.
2. Создайте локальный `.env` из `.env.example` или дополните существующий:

```dotenv
AI_PROVIDER=deepseek
DEEPSEEK_API_KEY=YOUR_NEW_KEY_HERE
DEEPSEEK_MODEL=deepseek-flash
```

3. В том же файле для параллельного запуска с v1.1 можно задать:

```dotenv
FRONTEND_PORT=8081
PROMETHEUS_PORT=9091
```

**Не добавляйте ключ в Git, README, скриншоты, команды, журнал или Frontend.** `.env` исключён через `.gitignore`. DeepSeek получает только название и описание события (с ограничением длины и базовой маскировкой секретов). IP/имена узлов из `labels` не пересылаются. Маскировка не гарантирует полного удаления персональных или конфиденциальных данных: подключение внешней модели является осознанным opt-in.

## Изолированный запуск на отдельном Docker Compose-проекте

Для защиты стабильную v1.1 предпочтительно не менять. Распакуйте ZIP ветки `ai-v1.2` в **отдельную папку**, рядом с v1.1, и создайте там собственный `.env`. Из новой папки:

```powershell
docker compose -p sentinel_ai_v12 up --build -d
docker compose -p sentinel_ai_v12 ps
```

Параметр `-p sentinel_ai_v12` обеспечивает отдельные контейнеры и тома, не затрагивая PostgreSQL v1.1. Обязательно использовать свободные порты 8081 и 9091 при одновременном запуске версий. Интерфейс открывается на http://localhost:8081.

## Как безопасно проверить, работает ли API-ключ

После запуска:

```powershell
docker compose -p sentinel_ai_v12 exec worker python -m app.deepseek_probe
```

Ожидаем `PASS: DeepSeek response received and validated` и название модели. Этот тест выполняет один реальный, потенциально платный запрос к DeepSeek, **не выводит ключ** и не изменяет инциденты. Он доказывает только доступность API и корректность структуры ответа, но не точность классификации.

Коды ошибок:
- `HTTP 401`: ключ недействителен или отозван.
- `HTTP 402/403`: возможная проблема с балансом или разрешениями.
- `HTTP 429`: превышен лимит.
- `FAIL: ... request or response error`: сеть, таймаут, формат JSON или другая ошибка.

Значение `AI_PROVIDER=rules` полностью отключает внешние запросы. Для обновления окружения после изменения `.env`:

```powershell
docker compose -p sentinel_ai_v12 up -d --force-recreate api worker scheduler
```

## Проверка классификации в интерфейсе

1. Войти под `admin`.
2. Включить сценарий отказа PostgreSQL в симуляторе.
3. Дождаться появления инцидента и анализа.
4. В карточке проверить источник вывода: `deepseek:deepseek-flash` при успехе или `expert-rules-v1+fallback` при ошибке.
5. Посмотреть категорию, критичность, гипотезы о причине, подобранный утверждённый регламент.
6. Не выполнять никаких реальных инфраструктурных действий. Сбросить сигнал симулятора и завершить тестовый инцидент вручную.

Если внешняя модель отвечает успешно, **процент уверенности не показывается**, так как он не калиброван. Гипотезы LLM требуют ручной проверки. При резервной классификации действует прежняя оценка правил.

## Тесты

GitHub Actions автоматически выполняет Python-тесты и сборку React. Новые юнит-тесты DeepSeek используют заглушки, поэтому не требуют ключа, не делают платных запросов и проверяют: отключённый режим, корректный JSON, отсутствующий ключ, HTTP 401, невалидные категории и редактирование чувствительных фрагментов.

Важное отличие: результаты 91,7% и 95,8% из v1.1 относятся **к прежнему локальному классификатору на синтетических данных**, а не к DeepSeek. Для оценки LLM нужна отдельная выборка, реальные запросы и независимо размеченные события.

## Безопасность и ограничения

- Любой текст внешнего мониторинга считается недоверенным вводом; модель получает инструкцию игнорировать команды внутри события.
- API-ключ хранится только в переменных окружения Backend/worker.
- Ответ модели проверяется по разрешённым категориям и уровням критичности.
- Приоритет вычисляется сервером и не принимается произвольным текстом модели.
- Новые команды, инструкции или шаги, придуманные моделью, **не становятся регламентами**.
- Рекомендованные регламенты подбираются прежней логикой базы знаний, чек-листы выполняются только вручную.
- При проблемах DeepSeek приложение автоматически переключается на локальные правила без остановки обработки инцидентов.
- Применение внешнего API требует согласия на передачу описаний событий стороннему провайдеру. При строгих требованиях к конфиденциальности используйте `AI_PROVIDER=rules`.
