# Sentinel AI v1.1 — безопасное обновление с v1.0

Версия **v1.1** заменяет исходники, но **НЕ требует очистки PostgreSQL или изменения существующих таблиц**.
Внешняя LLM через API намеренно **не подключена** — интеграция отложена на v1.2.

## Что изменилось

- Nginx резолвит адрес Backend через Docker DNS заново после пересоздания API-контейнера. GET-запросы фронтенда при 502/503/504 и сетевых сбоях повторяются с небольшой задержкой; POST/PATCH/DELETE автоматически не повторяются.
- Если загрузка не удалась, интерфейс показывает ошибку с возможностью повтора вместо ложного сообщения «Нет данных».
- Администратор может изменять регламенты в интерфейсе (версия повышается), восстанавливать из архива, безвозвратно удалять **только архивные регламенты, не связанные с рекомендациями инцидентов**. Для использованных инструкций сервер возвращает 409 — это защита аудита.
- В журнале включён фильтр «Скрыть закрытые» (по умолчанию); закрытые инциденты остаются в БД и аналитике. Снимки регламентов у прежних рекомендаций не меняются.
- Два прозрачных набора оценки локального rule-based классификатора: исходные 24 синтетических события и дополнительные 48 вручную написанных синтетических событий. Эти результаты **не являются независимым промышленным бенчмарком**.
- Публичная спецификация OpenAPI обновлена до v1.1.

## Обновление существующего проекта (Windows PowerShell)

1. **Не удаляй текущую папку проекта!** Скопируй текущий `Sentinel_AI` в резервную папку, если есть место.
2. **Создай дамп PostgreSQL** из **старой версии**, находясь в папке `C:\Users\ARDOR\Project_B2B\Sentinel_AI`:

```powershell
docker compose exec db sh -c 'pg_dump -U dutyai -d dutyai -Fc -f /tmp/sentinel_backup.dump'
docker compose cp db:/tmp/sentinel_backup.dump .\sentinel_backup.dump
```

3. Открой скачанный ZIP **Sentinel_AI_v1.1.zip** и **скопируй содержимое вложенной папки `Sentinel_AI` поверх твоей существующей папки `Sentinel_AI`** с заменой совпадающих исходников. Путь должен остаться тем же. **Не удаляй папку перед копированием.** `.env` не входит в ZIP, существующий `.env` сохрани.
4. В PowerShell в исходной папке выполни:

```powershell
docker compose config --quiet
docker compose up --build -d
docker compose ps
```

5. Открой `http://localhost:8080` и убедись, что внизу указано **v1.1**. Перезагрузи страницу `Ctrl+F5`.
6. Проверь, что регламент **PostgreSQLDown v2** и прежние закрытые инциденты сохранились (отключи «Скрыть закрытые», чтобы их увидеть).

### Очень важно

- **НЕ запускай** `docker compose down -v`, `docker volume prune` или ручное удаление томов.
- **НЕ создавай** новый Compose-проект под другим именем. v1.1 фиксирует имя `sentinel_ai`, что соответствует контейнерам v1.0 `sentinel_ai-...`.
- Если появилось HTTP 502, запусти `docker compose logs --tail=100 frontend api`; не удаляй данные.
- Если развернул архив в другой папке — сначала используй указанную инструкцию в старом пути, иначе Docker Compose может создать новые пустые тома.
- Если новая версия не подошла, верни исходники v1.0 на прежнее место и выполни `docker compose up --build -d` без удаления volumes.

## Проверка функций

**Из интерфейса admin:** «Регламенты» → «Редактировать» (увеличивается версия); «В архив» → фильтр «Архивные» → «Восстановить»; «Удалить навсегда» (для неиспользованных архивных; при наличии истории сервер даст 409).

**Из интерфейса operator:** нет кнопок администрирования регламентов.

**Инциденты:** включён «Скрыть закрытые». Сними галочку и убедись, что завершённые инциденты не удалены.

**Тесты** (все запускаются внутри контейнера, не требуют Python на Windows):

```powershell
docker compose cp .\backend\tests api:/srv/tests
docker compose cp .\scripts\evaluate_ai.py api:/srv/evaluate_ai.py
docker compose exec api python /srv/evaluate_ai.py

docker compose cp .\scripts\smoke_test.py api:/tmp/smoke_test.py
docker compose exec -e DUTY_URL=http://localhost:8000 api python /tmp/smoke_test.py
```

Для теста устойчивости: `docker compose restart api` → открой страницу и обнови её без перезапуска frontend. 502 должен исчезнуть после восстановления API. Это требует проверки на твоём компьютере; у меня Docker Engine недоступен.

## Ограничения AI

Рабочий классификатор v1.1 — **локальные экспертные правила**, а не LLM. Embedding по умолчанию — hash, а не нейросетевая модель. **Миграция на LLM API и neural embeddings запланирована на v1.2**, чтобы не рисковать работающим выпуском перед защитой. Даже 90%+ на синтетических выборках **не доказывают** точность на реальных событиях.
